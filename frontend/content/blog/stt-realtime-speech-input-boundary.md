**실시간 음성 입력에서 가장 중요한 경계는 사용자가 말을 마친 순간이었습니다. 말하는 동안에는 전사 결과를 빠르게 보여주고, 워크플로우에는 발화가 끝난 뒤 완성된 문장만 전달해야 했습니다.**

---

## 텍스트에는 전송 버튼이 있었습니다

XGEN Agentic AI Platform(이하 XGEN)에서 텍스트 기반 입력은 시작과 끝이 분명했습니다. 사용자는 내용을 모두 작성한 뒤 전송 버튼을 누릅니다. 서버에 도착한 문자열은 더 이상 바뀌지 않는 요청으로 확정되고, 워크플로우는 그때부터 실행되게 됩니다.

여기서 전송 버튼은 단순한 화면 요소가 아닙니다. 사용자가 “내 입력은 여기까지다”라고 알려주는 신호이기도 합니다. 저희는 이 명확한 경계를 전제로 워크플로우를 실행해왔습니다.

## 음성 파일은 입력 완료 시점이 분명했습니다

사람이 말한 음성을 글자로 옮기는 기술을 STT(Speech-to-Text)라고 하며, 음성을 글자로 바꾸는 과정을 전사라고 합니다. 저희가 먼저 적용한 음성 파일 전사는 이미 녹음이 끝난 데이터를 대상으로 했습니다. 입력 형식은 텍스트에서 오디오로 바뀌었지만, 어디까지 처리할지는 분명했습니다.

사용자가 음성 파일을 업로드하면 전체 내용을 전사하고, 완성된 전사문을 AI 에이전트에게 전달합니다. 워크플로우가 받는 값은 기존과 같은 문자열이므로 요약, 분류, 정보 추출 같은 흐름에도 그대로 연결할 수 있었습니다.

음성 파일 전사에서 해결해야 할 질문은 비교적 단순했습니다. “이 음성 파일을 어떤 AI 모델로 텍스트로 바꿀 것인가”였습니다. 음성 파일 업로드가 완료되면 입력이 모두 전달됐다는 것을 알 수 있었기 때문에, 언제 워크플로우를 실행해야 하는지는 별도로 판단할 필요가 없었습니다.

## 실시간 음성에는 입력 완료를 알리는 신호가 없었습니다

실시간 음성에는 전송 버튼에 해당하는 요청을 보내는 행동이 없습니다. 사용자가 “내일 서울”까지 말했을 때, 요청이 여기서 끝난 것인지 “내일 서울 날씨를 알려줘”라고 계속 말할 것인지 시스템은 바로 알 수 없습니다. 또한 사용자가 말을 이어가는 동안 전사문도 계속 업데이트됩니다.

그렇다고 사용자가 말을 마칠 때까지 화면에 아무것도 보여주지 않으면 시스템이 듣고 있는지 알기 어렵습니다. 반대로 전사문이 바뀔 때마다 워크플로우를 실행하면 완성되지 않은 불필요한 요청을 여러 번 처리하게 됩니다.

그래서 **화면에는 말하는 내용을 바로 보여주되, 워크플로우에는 사용자가 말을 마친 뒤 완성된 문장만 전달해야 했습니다.**

## 실시간 전용 모델 대신 스트림 처리 계층을 만들었습니다

앞에서 다룬 음성 파일 전사는 업로드된 음성 파일 전체를 STT 모델에 한 번 보내면 됩니다. 반면 실시간 음성 전사는 사용자가 말하는 동안에도 전사문을 보여주고, 언제 말이 끝났는지도 판단해야 합니다. 기존 STT 모델은 전달받은 오디오를 텍스트로 바꿀 뿐, 계속 들어오는 음성을 모으거나 발화 종료 시점을 판단하지는 않았습니다.

실시간 음성 전용 모델을 따로 운영하는 방법도 있습니다. 하지만 그러면 음성 파일 전사용 모델과 실시간 음성 전사용 모델을 각각 운영해야 합니다. GPU 자원이 제한된 환경에서는 두 모델을 동시에 올리는 것부터 부담이 되고, 배포와 장애 대응도 모델마다 따로 준비해야 합니다.

저희는 모델을 하나 더 추가하는 대신 기존 배치형 STT 모델 앞에 스트림 처리 계층을 만들었습니다. 이 계층은 들어오는 오디오를 30ms 단위로 나눠 소리 크기와 파형 변화를 살펴봅니다. 주변 소음 수준을 반영해 발화 시작과 종료 시점을 판단합니다. 

사용자가 말하는 동안에는 오디오를 버퍼에 모으고, 누적된 구간을 기존 STT 모델로 반복 전사합니다. 새 결과가 나오면 화면에 보이던 현재 발화문을 최신 결과로 바꿉니다. 아직 말하는 중이므로 단어가 더해지거나 앞서 보인 표현이 달라질 수 있습니다.

예를 들어 첫 결과가 “내일 회의 자료 확인해”이고 다음 결과가 “내일 회의 자료 정리해 줘”라면, 화면도 “내일 회의 자료 확인해”에서 “내일 회의 자료 정리해 줘”로 바뀝니다. 사용자는 말한 내용이 들어오고 있다는 사실을 바로 확인할 수 있습니다.

이때 화면에 보이는 문장은 완성된 요청이 아니라, 지금까지 들어온 음성을 바탕으로 만든 최신 전사 결과입니다. 빠르게 보여주는 대신 문장이 바뀔 수 있다는 성격을 그대로 받아들이고, 워크플로우 실행은 발화가 끝날 때까지 미뤘습니다.

STT 모델은 전달받은 오디오를 전사하고, 스트림 처리 계층은 오디오를 언제 얼마나 전달할지와 발화가 언제 끝났는지를 관리합니다. 역할을 이렇게 나눠 음성 파일 전사와 실시간 음성 전사에 같은 STT 모델을 사용할 수 있었습니다.

## 빠르게 보여주는 문장과 답변에 사용하는 문장은 달랐습니다

이처럼 말하는 동안 화면에 보여준 전사문은 사용자에게 진행 상황을 알리는 용도로만 사용했습니다. 사용자가 말을 더 이어갈 수 있고 문장도 바뀔 수 있으므로, 이 전사문만으로는 요청이 완성됐다고 볼 수 없습니다. 따라서 워크플로우에는 전달하지 않았습니다.

음성 활동 감지를 통해 발화가 끝났다고 판단하면 현재 오디오 버퍼를 마지막으로 전사한 뒤, 앞서 처리한 내용과 합쳐 완성된 전사문을 만듭니다. 이 전사문에는 사용자 요청이 모두 담겨 있어, 중간 결과보다 Agent가 질문 의도를 이해하고 정확하게 답변하는 데 적합합니다. 사용자에게는 실시간성을 제공하고, Agent에게는 완성된 입력을 제공하도록 전사 결과를 용도에 따라 나눈 것입니다.

```text
말하는 중 → 최신 전사문으로 화면 갱신 → 사용자가 듣고 있음을 확인

발화 종료 → 전사문 완성 → 워크플로우 자동 실행 → 정확한 답변
```

완성된 전사문만 기존 텍스트 입력 계약으로 워크플로우에 전달합니다. 따라서 기존 Agent나 워크플로우 노드를 다시 만들 필요 없이, 음성 처리 계층이 발화가 끝났다고 판단한 시점에 워크플로우를 자동으로 실행할 수 있었습니다. Agent가 만든 결과는 같은 대화 흐름 안에서 사용자에게 반환됩니다.

## 음성 입력 종료는 전송 버튼을 대신했습니다

실시간 음성에서 중요한 것은 글자를 만드는 일만이 아니라, 언제 한 요청으로 받아들일지 판단하는 일이었습니다. 이 경계를 세우자 사용자에게 전사 과정을 보여주는 일과 완성된 요청으로 답변을 만드는 일을 분리할 수 있었습니다.

**발화 종료는 화면에 보이던 전사문을 워크플로우가 처리할 완성된 요청으로 전환하는 경계였습니다. 텍스트 대화에서는 사용자가 전송 버튼을 누르지만, 음성 대화에서는 시스템이 그 순간을 판단합니다.**

이번 구현은 XGEN 오디오 기능을 실시간 대화로 넓힌 첫 단계입니다. 앞으로도 다양한 음성 환경에서 더 자연스럽게 대화할 수 있도록 관련 기능을 확장하고 다듬어갈 예정입니다.
